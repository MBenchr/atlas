# Trends Correlation Contract (Atlas)

Purpose:
- correlate architecture changes with degradation/improvement signals across 7/30/90 day windows
- provide causal reading for decision flow: `what changed`, `when`, `impact`

Canonical source:
- `data/atlas-history.json` (field: `trendsCorrelation`)
- generated by: `scripts/generate-trends-correlation.mjs`
- secondary artifact: `data/history/atlas-trends-correlation.json`

## Structure

`trendsCorrelation` includes:
- `generatedAt`
- `version`
- `windows`
  - `7d`, `30d`, `90d`
  - each window contains:
    - `sampleCount`
    - `fromGeneratedAt`, `toGeneratedAt`
    - `deltas` (`avgScoreDelta`, `gapDelta`, `graphEdgesDelta`, `graphNodesDelta`, `servicesDelta`)
    - `impactScore`, `impactLevel`
    - `sparkline` (`avgScore`, `gaps`, `graphEdges`)
    - `notableEvents` (event ids)
    - `causalRead`
- `notableEvents`
  - event list with:
    - `timestamp`
    - `whatChanged`
    - `signals`
    - `impactScore`, `impactLevel`
    - `whyLikely`
    - `source` (current/previous snapshot file)
- `domainWindows`
  - per-domain trend map for `7d`, `30d`, `90d`
  - each entry: `scoreDelta`, `trend` (`up|down|flat`)

## Usage in Atlas

- `history`: render correlation windows + notable events timeline
- `overview`: reuse latest notable event for quick causal context
- `domains`: use `domainWindows` deltas for trajectory read

## Governance

- Atlas renders this projection; correlation logic stays in generation script.
- UI must not recompute causal logic when `trendsCorrelation` exists.
- Contract evolution follows repo policy:
  - additive fields: `minor`
  - incompatible semantic changes: `major-with-migration`
